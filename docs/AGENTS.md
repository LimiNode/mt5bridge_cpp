# Documentation guide

`docs/architecture.md` is the canonical design and migration note. Record
durable choices there (or in `docs/adr/`) rather than growing `README.md` into
an experiment log. Keep README instructions synchronized with the actual build
and exported API.

Use [market-data-api.md](market-data-api.md) for control/data-plane contracts
and [mt5-quirks.md](mt5-quirks.md) for searchable MT5 behavior and upstream
references.

Research notes should state source, date, applicability, and an actionable
rule. Do not copy entire external articles into the repository.
